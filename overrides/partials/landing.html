SQL as a Python function.

AirSQL turns a decorated function into an Airflow task that reads, writes and moves data across PostgreSQL, BigQuery and GCS — without the operator boilerplate, and without SQL buried in keyword arguments.

$uv add airsql

The same upsert, written twice

On the left, plain Airflow: you write the ON CONFLICT clause and hope the columns stay in sync. On the right, the operation is the name.

The decorator returns a task: call it in your DAG the way you call any TaskFlow function. The SQL stays a string you can read, render with Jinja, or keep in a .sql file.

Every write you actually need

One decorator per operation. Each is also available as an operator class when you prefer >> wiring.

DecoratorWhat it does
sql.dataframeRun a query and return a pandas DataFrame to the next task.
sql.queryCreate a table from a query — no DDL to write.
sql.appendAppend the query's rows to an existing table.
sql.replaceReplace the target table's contents in one step.
sql.truncateTruncate, then reload — the cheap full refresh.
sql.mergeUpsert on conflict columns, with the update list you declare.
sql.load_dataframeWrite a DataFrame into a table without hand-rolled inserts.
sql.merge_dataframeUpsert a DataFrame against an existing table.
sql.extract_and_loadCopy a query's result from one connection to another table.
sql.extract_and_mergeThe same hop, merged into the destination instead of replaced.
sql.checkA data-quality assertion: the task fails when the query says so.
sql.ddlCreate, alter or drop, with the same connection handling.

Sensors that wait properly

Poll a query until it returns true, with retries and poke intervals instead of a sleep in a PythonOperator.

  • PostgresSqlSensorWait for a condition in PostgreSQL.
  • BigQuerySqlSensorWait for a condition in BigQuery.

Both are deferrable-friendly and take the same connection and SQL you already use elsewhere.
